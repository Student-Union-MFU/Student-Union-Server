Connection pool

When latency climbs, read empty acquires first. Flat means the pool is innocent and the cost is inside Postgres. Climbing means requests are queueing for connections, and only then is DB_MAX_CONNS worth revisiting.

Go runtime

Auth throttle

Capacity exceeded means the backlog was full and the caller was refused instantly — raise AUTH_THROTTLE_BACKLOG. Timed out means it queued and waited the full timeout — raise throughput; a bigger backlog makes this one worse.

Long-poll and push

A waiter count that only ever grows is a missing Release(), which is a goroutine leak. A listener that is not connected degrades chat and SOS to 25-second latency with no error anywhere.

pg_stat_statements is not answering. It is the single highest-value number on this page — it would have found the query that made the server slow on 2026-08-22 in seconds, ranked by the time it really consumed, from real traffic. To enable it: add command: postgres -c shared_preload_libraries=pg_stat_statements -c pg_stat_statements.track=all to the database service, apply migration 000027, then restart Postgres — it is a postmaster-level setting and a reload will not do.
